# RAG-jina

Build a small, independent Late Chunking learning project. Follow `docs/SPEC.md`.
Use Python 3.13.9, uv, pyproject.toml, and uv.lock; do not introduce requirements files.
Use Ruff with E, F, I rules and a 100-character line limit.
Keep code readable and explicit. Work incrementally so each step can be reviewed.
Add offline pytest coverage alongside each implemented step and run it before handing off.
Do not add production features, UI, APIs, agents, or a general evaluation framework.
Use Jina's reference approach when implementing contextual token pooling.
Preserve the same financial corpus used by the other learning projects.
